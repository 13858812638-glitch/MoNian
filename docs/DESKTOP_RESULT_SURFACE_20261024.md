# 桌面结果列表：移除侧滑入口并统一行状态

唯一开发基线 `9fa2631`，即上一轮已交付的完整修复版。按本轮明确需求修改桌面结果列表；不是新冻结版本。

## 实现与职责

- `SearchCore` 只在移动端创建 `SwipeActionCoordinator`。桌面侧栏、Tab、普通窗口、Embedded 均没有该控制器、文档捕获监听或逐卡手势绑定。关闭/挂起路径支持没有侧滑资源的宿主。
- 移除结果卡“…”节点、CSS、点击入口、`desktopTrigger` 参数、`openFromTrigger`、专用展开 class、点击吞掉标记、对应焦点例外与行高判断。生产源码中这些旧标识零引用。
- 桌面不再创建批量工具栏的“展开全部左滑按钮”。移动端侧滑、触控笔、批量展开继续使用原有状态机与五个动作，不复制另一套结果业务实现。
- 结果外壳继续承担虚拟位置、分割线和行高观察。保留这一共用 DOM；只有带真实移动端动作绑定的外壳拥有展开动画。桌面没有隐藏的动作面板或后台动作刷新。
- 行高回调先检查是否存在侧滑能力：桌面跳过侧滑 class 查询与 `_sampleSwipeReveal`，继续直接使用 ResizeObserver 的真实高度；不新增几何缓存或后补刷新。
- 桌面悬浮背景使用已有 `--ls-control-surface-hover`；选中背景、左标记、内边框直接加入 Picker/导航行的共享规则与 Token 作用域，圆角使用 `--ls-picker-row-radius`。不新建 Style Settings、不用 JS 写视觉尺寸。
- 普通点击继续打开文件，同时更新现有 `selectedIndex` / `is-current` 结果游标；键盘沿用这个游标，批量选择仍由 `SearchSelectionController.selectedPaths` 拥有。没有增加“当前文件”缓存、活动文件监听或查询发布。单击高亮不执行搜索或结果重绘；重新搜索按原生命周期清理游标。
- 右键文件菜单、元数据筛选、批量工具栏与移动端 Picker 保留既有入口和焦点规则。

样式 owner 是共享行状态规则，实时业务 owner 仍为原 SearchCore/Selection。没有把 `display:none` 当成移除事件的替代措施，也没有增加新的窗口弹窗定位规则。

## 验证与证据

`scripts/desktop_result_surface_audit.py` 使用真实 SearchView 初始化链，在明暗主题的桌面及移动模拟中验证：

- 无桌面动作节点、控制器和绑定；CDP 检查单行没有侧滑 pointer/touch/click 监听。
- 悬浮颜色及选中背景/边框与筛选行 computed style 一致。
- 连续点击只保留一个当前游标，键盘继续向下；点击调用原打开入口一次，结果重绘为零。
- 悬浮和选中不改变行宽高；批量选择、右键入口、重新搜索正确。
- 其他桌面宿主同样没有侧滑生命周期。
- CDP 实际触摸序列仍能在移动模拟中打开五个动作，移动批量展开仍工作。

同一脚本也在隔离的 `9fa2631` 源码上运行，保留前后 JSON。复用卡片专项将旧桌面侧滑用例移至移动端，继续验证展开动作时禁止复用、已打开动作卡返回时重建；桌面改为验证没有动作生命周期且普通卡可复用。未删掉移动行为断言。

本轮最初测试发现共享选中 Token 只在 Picker/导航作用域生效，桌面结果背景为空。修正为把结果容器加入同一 Token 定义，未复制颜色常量。测试脚本还修正了 Playwright 将赋值表达式返回的函数当作待调用函数的问题；旧卡片用例对已移除的桌面侧滑对象的调用已迁移到移动端。上述校正不增加生产兼容分支。

最终专项 36/36 通过；基线同一脚本 18 通过、18 未满足新合同。桌面单行原有 click/pointerdown/touchstart/touchmove/touchend/touchcancel 六个侧滑监听全部移除，只保留键盘入口；一次 16 行的行高回调中，侧滑高度采样由 16 次降为 0。普通行高测量继续保留。这些是受控调用量，不是整插件提速百分比。

工程检查、构建通过；最终 Node 272 项中 268 通过，4 项与基线相同的历史契约失败。完整搜索条件验收、焦点、焦点修复、Picker 光标/Portal Chromium、移动侧栏、索引重试通过；旧 A/B 仍在四种配置的初始快照处失败；本轮也包含明确授权的 DOM/视觉变化，不能将旧快照比较替代新交互验收。最后的行高短路修改后重新构建，重跑 Node、36 项交互专项、卡片复用、生命周期与样式审计；未用旧包代替最终构建交付。

完整结果与初轮记录：`reports/desktop-result-surface-20261024/test-summary.json` 及同目录证据。仍然区分受控 Chromium、Node 与原生 Obsidian：本轮没有原生桌面/iOS/Android 实机、WebKit 或用户第三方 CSS 组合验收。不宣称完整测试全绿或全场景卡顿已消失。

## 覆盖安装

交付仅含同一次构建的 `main.js`、`styles.css`。关闭 Obsidian 后覆盖原插件目录这两个文件，保留 `manifest.json` 和 `data.json`，重新启动。压缩包执行 CRC 和 dist 字节校验，下载后再次比对。
