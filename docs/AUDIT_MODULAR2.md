# GLS Navigator 搜索／筛选状态与全源码审计

## 结论与边界

本轮唯一修改基线是本会话已经交付的 modular.1 源码工程；修改发生在 `src/`，运行 main.js 由构建重新生成。不是回到最初聚合文件上追加补丁。

已定位并修复：纯搜索产生空条件栏、退出零命中创建预览后残留 Draft 条件 Chip、返回导航保留不可见旧查询而使计数继续受限、快速改词再点筛选使用旧提交词，以及编辑框已空但提交态仍有词时清空入口误判为空。

光标投诉没有在本环境复现。原版和新版的原生 DOM 输入控件都能通过 Chromium 点击／触控模拟获得焦点、输入文本并保持折叠选区；完整移动 WebKit、Obsidian 宿主及用户实际主题/片段仍未验证。本版没有增加假光标、caret 覆盖层或 blur → rAF → focus 补救链。

**审计覆盖整个源码树的结构、依赖、原始片段、样式与资源登记，并对搜索相关跨模块调用链做了逐项追踪和动态对照；不等于所有业务、所有设备与所有第三方集成都已实机验收。** 尚有明确列出的全插件收口项目，不能称“全插件封盘”。

## 根因一：关键词与条件栏混为同一个显示条件

`core/search/shell-methods.js::_syncResultStateRow` 原来把 `queryState.active` 和创建视图也作为“清空”和整栏的显示条件。因而只有文本、没有真实 Chip 时，也能得到一条空栏。结果频道又允许只有标题或只有正文时建立只有一个选项的组，进一步让纯关键词显示为“条件”。

本版用当前真实 Chip 和有实际切换价值的双频道控制整栏。关键词由主输入与原橡皮擦负责；默认创建类型由 Composer 负责，不冒充可删除条件。标题与正文都有匹配时，原频道切换仍保留，并非删除标题/正文搜索功能。

原移动导航 CSS 另行隐藏频道，与 JS 同时决定一个可见性结果。本版移除这条重复控制：`hidden / aria-hidden` 由 `_syncResultStateRow` 统一写入，`syncPage` 在页面变化后通知它，CSS 只负责组件布局。

## 根因二：创建预览退出只交还数据指针，没有交还投影

零命中创建预览与主动创建不同。派生预览保存原搜索 FilterState，把 core.filterState 暂时指向 CreateDraft。用户随后在 Picker 修改的是 Draft，而不是搜索条件。

原 `_leaveDerivedCreateView` 恢复了搜索 FilterState，却只同步输入模式，没有同步 Chip、类型按钮和筛选池。橡皮擦触发新查询时先经过这个退出入口；稍后渲染发现已经不在创建态，不再进入另一分支的刷新逻辑。于是数据已经恢复，DOM 仍留着 Draft Chip。清空入口看到真实数据已空又提前返回，看起来就像“点清空也没用”。

本版把恢复指针及筛选投影放在同一个 `_leaveDerivedCreateView` 中，删除 `syncDerivedCreateViewState` 中另一退出分支的重复刷新。橡皮擦、新查询、返回等调用同一退出入口，不分别补 DOM，不新增一份搜索或创建状态。

对照同时验证：原来没有筛选时退出后确实全空；原来已经选择“项目”目录、预览里改成“资料”时，退出后恢复“项目”，不是把所有筛选一概清掉。

## 根因三：返回导航只改页面，不结束文本查询

旧 `setPage("filters")` 只改变页面。手机输入栏可以隐藏，但 `QueryState.raw` 仍有旧词；Navigator 的候选集合按当前查询计算，因此零命中的旧词自然让多种计数继续为 0。这是隐藏查询仍生效，不是已证明索引文件损坏。

本版在统一导航返回入口提交空查询、取消既有输入防抖并保留真正的筛选条件。底部返回、普通返回、折叠导航和侧栏工具复用这一入口。已经停留在筛选页时，再明确点击返回命令也能结束残留查询。

计数仍使用 `_facetUniverse → _facetCandidates → Navigator generation/cache` 的原链，不新建独立“导航统计数据”。同一维度计算候选时仍忽略该维度自身，不改变原来同维度可追加/OR 及跨维度匹配规则。合法的零结果仍会显示 0，不强制把所有 0 改成全库数量。

## 根因四：输入防抖与筛选提交读取不同时间点

文本变化使用既有 150ms 防抖，而 `_onFilterChanged` 默认取已经提交的 `queryState.raw`。用户刚输入新词就点筛选，筛选重搜会取消旧计时器，却用更早的词，造成“输入框是新词，结果还是旧词”。

本版默认从同一个实时 searchInput 读取；处于 composition 时仍使用已提交值，等待 compositionend 再提交完整文本。明确传入查询的已有调用继续按原参数执行。不增加计时器或中间状态。

另外，清空入口同时检查实时输入和已提交 Query，而不是只因编辑框当前为空就跳过清空。

## 唯一 Owner 与实际改动

实际修改五个 JS 源模块及一个 CSS 源文件：

1. `src/core/search/shell-methods.js`：条件栏显隐及清空判定。
2. `src/core/search/input-and-filters-methods.js`：筛选提交时读取实时输入／组合输入保护。
3. `src/features/create/input-mode-methods.js`：派生创建退出的数据与投影交接。
4. `src/features/navigator/SearchNavigatorController.js`：统一返回查询清理及页面显隐通知。
5. `src/features/results/filter-channels-methods.js`：只有真实双频道才显示切换组。
6. `src/styles/styles.css`：删除重复频道显隐选择器、增加版本说明；未改光标规则和参数默认值。

删除的是错误显示条件、退出分支的重复刷新及 CSS 的平行显隐控制。保留的是原 FilterState、QueryState、CreateDraft、Facet 组件、Navigator 缓存与搜索提交链。没有新增生产模块、持久字段、DOM 组件、监听器、timer、rAF 或单独的移动状态机。

153 个 JS 模块中 148 个逐字未变。总源码净增 19 行／1,232 字节（包含注释和 CSS 版本头）；不是根据文件大小推断性能提升。

## 全插件收口尚未完成的项目

### 光标：尚未复现，不能称已修复

本次测试新增真实 Chromium click/tap 后输入，而不是只调用 input.focus；又新增主输入已聚焦并存在输入防抖时进入 Picker。测得可编辑、命中 input、焦点保持、选区折叠在文本末尾、caret 颜色非透明。证据截图使用 `caret="initial"`，没有像旧像素比较那样隐藏光标。

但这些仍不是手机原生 WebKit。未取得当前主题、其他插件 CSS、用户 CSS Snippet、原生视频和系统版本，不能断言它们导致问题，也不能断言当前 CSS 颜色就是唯一根因。

### 跨插件样式范围需三端共同核对

当前 CSS 约 6967 行后存在 `--ui-mobile-*` 全局 Token 以及 `.pwb-*`、`.dida-bridge-*`、`.ui-picker-*` 选择器；它们是这份基线已有的共享合同，不是本轮添加。没有工作台与任务插件完整源码和加载顺序，不能证明同一视觉状态确实只有一个 Owner，也不能擅自删除并改变它们的 UI。

### 键盘合同与最新标准存在差异

现代码的移动外框为 83.5dvh，MobileFrameController 保留预键盘外框并按遮挡量给当前输入所属滚动区让位。源码并没有用户本轮写明的 `min(520px, 55vh)` 键盘高度上限 Token。这里明确列为尚未归一项；本轮没有顺带换键盘策略，以免在原生光标未复现时再改变同一条高风险链。

### CSS 扫描命中不是一律删除

有两组同上下文重复 selector：`:root` 与 `body.is-mobile`，承载不同 Token 区段，不能直接称同属性冲突。八处重复 `overflow` 均为先 `hidden` 后 `clip` 的兼容声明；最低 Obsidian/浏览器版本未知，不把它们未经兼容核对就删掉。Style Settings 重复 ID、同名根 heading、无引用 Token/参数候选均未发现；这只是扫描结果，不等于每个参数的实机极值已验证。

## 测试方法与初轮失败

原版 A 明确使用冻结 modular.1 的运行主体及 CSS，B 使用当前模块构建，绝非两边都加载新 CSS。

既有功能 A/B 比较排除获授权改变的条件栏 DOM；结果卡 Y 按实测条件栏高度换算，以免把删除空栏后自然向上占用空间当成错误。其他 DOM、坐标/尺寸、焦点、状态和文件结果严格比较。创建预览的一个截图用新的“空条件栏隐藏”断言，而非声称与旧缺陷像素一致。新增专项独立断言正确结果，不只断言 A 等于 B。

历史失败完整保留，不计入最终通过：

- 默认 npm 离线缓存未命中；一次联网安装超时；随后指定容器已有 `/root/.npm` 缓存安装成功。
- 初轮 Node 97/98：失败是旧测试要求 CSS 必须逐字不变。本轮有明确授权的显隐规则变化，改为完整源码冻结 + 逐文件批准哈希，不是删掉 CSS 审计。
- 初轮专项 104/108：桌面计数断言使用 textContent，把辅助 aria 文本拼进数字得到 NaN。已改为读取实际数字文本节点，原产品没有因此改代码。
- 旧浏览器第 6 场景只调用私有“修改值”函数，没有调用真实事件路径随后必走的 `_onFilterChanged`，构造了不成立的半提交状态。修正为完整正式提交并增加 Chip 存在断言。
- 旧浏览器第 16/17 场景把删除空栏造成的 34px 结果上移当作回归。加入实测条件栏高度归一；销毁后从 DOM 获取该高度，而非已清空的 core 引用。没有放宽其它几何字段。

最终数字与可复现构建记录附在文末，原始日志在 `reports/current/final-verification.log`。

## 实机验收步骤

先备份插件，在测试仓库覆盖 main.js 与 styles.css，保留原 manifest/data，再完整重启 Obsidian。

1. 无筛选时搜索一个仅标题命中的词，以及完全没有命中的词：不出现空“当前条件/清空”行。标题与正文都有匹配时，原频道仍能切换。
2. 从无命中创建预览修改文件夹、标签或属性，然后点橡皮擦：Draft 条件消失。另以预先选定文件夹进入预览，退出后应恢复原文件夹，不应恢复预览中临时选的文件夹。
3. 输入一个会得到 0 结果的词，再按底部返回/返回箭头/折叠导航：输入词被清空，真实筛选保留，各计数按保留的条件计算。再次进入结果页不应复活旧词。
4. 快速改搜索词后立即点筛选，结果应使用当前完整输入。使用中文输入法组词，未确认的半个词不应提前搜索。
5. 分别检查文件夹、标签、属性键、属性值以及创建模式的三个元数据 Picker：空输入、连续输入、点中间移动光标、已开键盘时换入口、清空后再次输入。检查真实插入光标、键盘和外框，不只检查文字是否能输入。
6. 检查重命名/删除、多选、滑动和长列表滚动；打开 Picker 后关闭/卸载插件，确认无遗留浮层。真实多窗口/NAS/外部工作台接口另按 MANUAL_ACCEPTANCE.md 验收。

光标仍异常时，需要当前运行版本下的操作录像以及 Obsidian/系统版本、主题和启用的相关样式信息；无需发送仓库正文或 data.json。
