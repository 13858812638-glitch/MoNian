# 输入与 Picker 重复工作精简 · 2026-10-23

唯一开发基线：`90f1ade`，即上一轮已经交付的 Owner 修复版。按用户“开始”继续优化；未更换冻结基线、未从旧上传包回填实现。

## 本轮根因与修改

| 路径 | 原因 | 当前实现 |
| --- | --- | --- |
| 主输入 → 防抖 | `_commitSearchInputValue` 在提交查询前调用完整 `_notifyStateChange`，比较旧查询、同步导航；最终搜索再次通知 | 编辑缓冲只请求宿主保存；`performSearch` 拥有正式查询提交通知，创建输入由 `handleInput` 通知 |
| 原生 input → 导航工具栏 | 每次输入遍历工具栏配置、目录、按钮、图标，实际只有输入非空标记发生变化 | `syncNavigatorQueryVisibility` 是该显隐标记的唯一实现；原生输入与工具栏正式同步共用它，实时输入不再遍历工具栏 |
| 页面显隐同步 | 同一页反复写 `data-nav-page` 和 `hidden` | 使用已有同值写入 Primitive，状态相同不写 DOM；页面切换、锚点和条件行语义保留 |
| Picker 计数对齐 | 首次动画帧与 ResizeObserver 都读取宽度并写同一 CSS 属性；高度变化也会重写不变的滚动条预留 | ResizeObserver 负责首次与后续布局，直接比较当前属性再写；关闭时断开观察并拒绝晚到回调 |

只修改三个生产 JS 模块。CSS、Style Settings、Snippet 控制链、尺寸默认值、焦点、键盘、手势、持久化格式和公开 API 没有改动。桌面和移动复用同一实现；未新增业务缓存、延迟定时器、发布通道或第二套 UI 状态。

没有直接让 `setPage` 同页提前返回：同页返回导航仍可能需要结束查询、退出批量、兑现待处理投影。也没有删除待输入时的宿主保存请求：`captureSession` 必须保留尚未防抖提交的实时输入。这些是必要工作。
