# 侧栏属性展开与隐藏刷新审计 · 2026-10-22

用户反馈桌面侧栏的属性键没有展开入口，并要求继续排查刷新、重排和卡顿。本候选在既有侧栏优化上修正属性交互，未晋升正式冻结版本。

## 修正行为

桌面属性键原先被独立分支直接送入共享 Picker，没有树形展开动作。现在仅桌面 sidebar 的属性键和箭头都能原地展开/折叠；子行点击应用属性值，再点同一个值取消选择。其他桌面宿主保留原 Picker 入口，移动端保留原展开方式。

属性键和展开的值使用全局导航目录；切换文件夹时保留零计数项和原有行节点，只更新当前目录计数和选择状态。空值、false、0 都有可选子项；空值是固定筛选状态，不能当成真实值拖拽迁移。超过 60 个值时保留“显示全部”共享 Picker 入口，右键管理入口继续可用。

## 减少的工作

- 未展开的键只使用一次扫描生成的属性存在计数，不收集、排序它们的全部值。
- 已展开键的全局值模型按需生成，当前文件夹的计数仅保留一个范围；查询和属性选择变化复用统计。真实元数据、目录、属性目录和偏好变化通过既有失效流程更新，没有第二套索引。
- 属性值稳定投影直接更新原节点的计数和选择，不重建整段列表；统计和选择分别维护，避免选择变化造成重新扫描。
- 隐藏的标签/属性分组不再更新内部行。保留它的旧 generation，重新展开时在投影中更新计数与选择，随后绘制。
- 沿用稳定结构下跳过逐行布局测量的路径；没有增加点击防抖或延迟搜索。

## 验证与边界

新增 `scripts/sidebar_property_expansion_audit.py`：34 项检查，覆盖行/箭头/键盘展开、连续点击、零计数、DOM 保留、隐藏分组重开、空值保护、元数据/目录/删除失效、其他宿主分支及 2400 文件场景。原固定目录测试中“点击属性键打开 Picker”的断言按本次明确需求改为“展开全局值”；其余断言保留。

初始 21 项复现检查中 11 项失败。修正展开后，追加审计还确认了隐藏分组的多余工作，以及空值不应参与拖拽；各阶段失败证据均保留。

| 受控操作 | 结果 |
|---|---|
| 分组隐藏后切换文件夹 | 内部 DOM 变更从 9 次降至 0 次；属性值统计从 1 次降至 0 次 |
| 同一目录连续点属性值 6 次 | 恰好提交 6 次搜索，额外导航统计构建 0 次 |
| 不变状态投影 8 次 | 属性内容 DOM 变更 0 次 |
| 折叠/展开 12 次 | 搜索 0 次、额外值模型构建 0 次，箭头仍只有一个 |
| 2400 文件、80 个属性值，切换目录后连续点值 10 次 | 切换目录时仅计算该键 1 次；后续统计扫描 0 次、原有值行保留，导航逐行布局读取 0 次 |

详细结果见 `reports/sidebar-properties-validation.json` 和同前缀的阶段报告。静态检查、构建及受影响浏览器回归结果均记录在报告中。全量 Node 仍有 4 项既有原型/冻结基线差异，旧浏览器 A/B 仍有 4 项初始快照差异；未修改冻结基线或放宽这些断言。

测试环境为 Chromium 和模拟 Obsidian SearchView 生命周期。以上是执行次数/DOM/几何读取统计，不能等同于原生 Obsidian 的帧率或输入延迟。原生桌面、iOS/Android、WebKit、真实第三方集成仍待实机验证。
