# 滚动测量精简与性能试验 · 2026-10-23

唯一开发基线 `176d307`。落实 [上一轮性能审计](PERFORMANCE_AUDIT_20261023.md)，最终交付只修改一个共享 JS 模块：`viewport-geometry-methods.js`。CSS 与本轮基线逐字节一致。

## 保留的优化

`_setScrollTop` 是程序滚动的唯一入口。归一后的目标为 0 时，该位置对任意滚动范围都有效，省去 `scrollHeight` 与 `clientHeight` 两次上界读取；当前 `scrollTop` 只读一次，不在同值返回时重复读取。正数目标继续按真实上界限制位置，保留程序滚动标记、亚像素阈值及返回实际位置的合同。

没有新增缓存、计时器、状态源、延迟提交、第二套组件或输入路径。之前的顶部命令栏、搜索条右置、属性展开、上下/左右分栏调节继续保留。

## 未交付的试验与原因

先后验证了滚动区尺寸隔离、flex-basis 调整、行级/根级 containment，以及原生 `content-visibility: auto`。这些都是从本轮基线派生的临时试验，没有取用旧版本代码。

根节点 `contain: strict` 虽然明显降低单独的 Layout 耗时，但 UpdateLayoutTree 同时增长，抵消收益。去掉部分 containment 或查询容器能力也没有得到稳定净收益，均撤回。

固定高度导航行的离屏渲染通过了功能检查，但最终串行对照发现取舍：

| 文件数 | 操作 | 修改前渲染合并值 | 试验版渲染合并值 | 变化 |
| --- | --- | ---: | ---: | ---: |
| 161 | 切换文件夹 | 1229.3 ms | 1061.1 ms | 减少 13.7% |
| 161 | 展开/折叠 | 224.4 ms | 185.4 ms | 减少 17.4% |
| 2400 | 切换文件夹 | 929.6 ms | 992.9 ms | **增加 6.8%** |
| 2400 | 展开/折叠 | 812.7 ms | 656.2 ms | 减少 19.3% |

上述为**已撤回试验**，不是交付版提速成绩。每项是两轮的平均值，每轮 24 次操作；受控 Chromium、CPU 4 倍降速，完整回归后串行执行修改前 → 修改后 → 修改后 → 修改前，前版固定 JS 和 CSS。渲染合并值按线程合并 Layout / UpdateLayoutTree / Paint 区间，去掉嵌套重复，不包括全部 JS 工作，也不是输入到画面的延迟。

由于文件夹切换是用户主要痛点，不能为展开收益接受该场景的倒退。行级固定尺寸隔离也未消除这个问题，因此最终交付**撤回全部 CSS 试验**。原始逐轮数据及拒绝原因见 [性能记录](../reports/smooth-layout-performance.json)。

## 验证与实际边界

新增专项在同一基线为 11 项通过、2 项失败，交付版为 13 项通过：滚动归零测量次数、正数上界、远处键盘焦点、节点保留、行高设置及不同宽度下的可见区覆盖。零/负数/NaN 三次归零操作的上界读取由 `scrollHeight` 3 次 + `clientHeight` 3 次变为均 0 次。

初版测试曾在移动结果页测量隐藏导航行，得到 0 高度；已修正为先切回导航页，初版日志保留。试验版专有的 containment / content-visibility 断言随被拒绝方案单独归档，不当成交付版功能合同。

最终当前行为检查 **1260 项通过**，工程检查与可复现构建通过。完整回归结果见 [验证报告](../reports/smooth-layout-validation.json)。Node 的 4 项既有冻结原型差异、历史浏览器 A/B 的 4 组初始快照差异单独保留，冻结参考与断言未修改。

**本轮是确定多余工作的小幅精简，尚未解决整体卡顿。** 结果提交仍需读取真实滚动位置和视口，以维护失败回滚和首屏覆盖；每次切换中的同步 Layout 仍存在。没有以缓存的旧尺寸或异步补画换取虚假的零布局成绩，也没有证据证明这两次 getter 的减少能带来明显体感提升。

未验证原生 Obsidian、iOS/Android、WebKit 和用户实际资料库。测试宿主的结果不能代替实机交互验收。
