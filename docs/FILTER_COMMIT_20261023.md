# 筛选提交优化 · 2026-10-23

唯一开发基线为 `e38dea9`，落实上一轮 [性能空间审计](PERFORMANCE_OPPORTUNITIES_20261022.md)。修改 5 个共享 JS 模块，桌面与移动端消费同一实现。CSS、Style Settings、片段、持久数据与插件身份没有变更。

## 已实施的根因修复

### 条件组件按身份更新

`SearchFacetController.renderPinnedPropertyFilters` 不再清空整行。条件组、组按钮、值按钮与独立条件按钮由既有 Condition Group Primitive 按语义身份复用：文件类型、目录、标签、属性键、时间具有互不冲突的身份，属性“标签”不会与标签筛选组混淆。

每次从当前 DOM 提取组件节点，当前显示和动作直接由 FilterState 推导。按钮只注册一次点击监听，动作引用随投影更新；没有新增持久缓存、第二份筛选状态或桌面/移动分支。移除单个条件只移除相应节点，其他条件与焦点保留。

可见文本由 `setDomText` 更新，无障碍名称由既有 Hover Owner 更新。提交只管理条件组件的子节点，保留 Hover Owner 创建的隐藏标签；不调用 `focus()`、`blur()`，不在删除按钮后补一次焦点恢复。

### 筛选事务先复位滚动，再写入控件

正常筛选由 `_onFilterChanged` 将 `refreshFacets` 意图交给 `performSearch`。后者先在原布局上复位滚动，再更新条件和筛选条，随后重算并提交结果。创建视图仍由原 CreateFlow 负责。

结果页继续读取条件行改变后的真实视口尺寸，保留真实滚动边界、HeightIndex 和失败回滚，未增加定时器、延迟选中态或几何缓存。索引批次的筛选条刷新与显式筛选同次到达时只刷新一次；仅索引更新的刷新仍在原提交位置。

此改动消除筛选控件写入之后、滚动复位之前的同步布局。结果页提交仍需几何读取，尚有一轮同步布局；本轮没有将其隐藏为异步，也不宣称彻底消除了布局成本。

### 结果提交复用本次已知信息

`renderPage` 只计算一次窗口预算，并传给 `_windowStartForPosition`。提交直接遍历已构建的 item 注册高度观察，再将同一序列交给 `_syncMountedState`，避免重复查询已知的 shell/item。

`_syncMountedState` 仍是挂载状态唯一装配入口，滚动窗口提交可以从实际 DOM 推导。高度观察器的代际重新注册、滚动追加、频道映射、内容失效、选中状态和完整失败回滚均保留。没有放大 96 张卡的缓存，也没有减少可见区覆盖。

受控 Chromium、CPU 4 倍降速，161 文件与 2400 文件两组样本，24 次真实鼠标切换：

| 工作量 | 修改前 | 修改后 |
|---|---:|---:|
| Layout 总次数 | 72 | 48 |
| 滚动复位方法内同步 Layout | 24 | 0 |
| 窗口预算计算 | 48 | 24 |
| 结果提交的 `_mountedShells` 重扫 | 24 | 0 |
| 相同条件同步 8 次的 DOM MutationRecord | 28 | 0 |
| 相同条件同步后原按钮及其焦点 | 丢失 | 保留 |

折叠仍为每次一次布局；未修改导航的大树挂载策略。上述是工作次数变化，不能解释成整体速度提升三分之一。浏览器样本的绝对耗时和主线程采样受宿主、CPU 降速与自动化环境影响。

全部回归结束后，单独按修改前 → 修改后 → 修改后 → 修改前串行运行连续点击对照，每种规模每侧 100 次筛选。下表测量从 `select` 开始到导航微任务提交，**不含后续绘制，不是原生设备的输入到显示延迟**：

| 样本 | 修改前平均 / P95 | 修改后平均 / P95 |
|---|---:|---:|
| 161 文件 | 22.64 / 54.60 ms | 19.73 / 49.60 ms |
| 2400 文件 | 26.67 / 46.30 ms | 25.86 / 50.40 ms |

小样本平均耗时降低约 13%；大样本均值只降低约 3%，P95 未改善。大库尾部延迟仍有波动，不能据此承诺所有操作都已经流畅。详见 [完整对照数据](../reports/filter-commit-benchmark.json) 和 [布局/工作量证据](../reports/filter-commit-layout.json)。
