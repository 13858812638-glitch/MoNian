## 根因与最小修复

冻结版本 `SearchCore._recomputeCurrentResults()` 对每次后台索引增量更新，无条件推进 `_resultGeneration` 并清空 `loadedPaths`。随后的 `refreshChangedRows()` 重新调度当前窗口摘要，`_lazyFillSnippet()` 无条件重写所有可见摘要 DOM。改变一份离屏文件时，18 张可见卡不重建，但摘要却全部重写。

**本轮仅改动 3 个运行源码模块：**

1. `src/core/search/search-and-ranking-methods.js`：增量数据代次继续推进以阻止旧异步写回，但只失效变化路径和仍在途未提交的摘要；已完成且未受影响的摘要保持可用。显式重新搜索与全量结果计算仍按原规则清空加载记录。
2. `src/features/results/SearchResultRendererController.js`：由现有 Result Renderer Owner 维护一个小型在途路径 generation Map，在销毁时清理；不是第二套结果缓存、事件中心或持久化状态。旧任务清理时按 generation 对比，不能删除新代次任务。
3. `src/features/results/page-and-snippets-methods.js`：仅回填本次真正完成的新摘要，不再无条件遍历整屏改写 DOM；在途路径直到**整批 DOM 提交结束**才算完成，避免读取已经完成但整批等待时恰好发生后台更新导致永久漏绘。

未改 `refreshChangedRows()` 的卡片替换行为，未改 QueryState、排序、筛选、创建态、虚拟窗口、滚动、Pointer/Swipe、Picker、外部工作台接口、CSS、插件 ID 或数据 schema。模块仍是 146 个、静态依赖仍为 635 条；未新增监听、定时器、观察者或主动刷新循环。
