# GLS 文件夹导航与分割线 v2（候选）

## 唯一起点
基于 2026-10-18 正式冻结的“导航范围与精筛分离 v1”，从 `src/` 修改。上一轮“分割线样式统一”只是对照问题样本，未把该 ZIP 当作基线；本轮重新解决自动分组线和手动分割线。仍为候选，正式基线没有自动升级。

## 根因与改动
1. `sharedFolderChildren` 曾用 `isPathExcluded` 同时控制目录可见性与索引可见性，导致自动排除的 `90-附件/GLS-元数据` 在导航中消失。新增 `showProtectedMetadata` 仅供侧栏导航使用；普通创建/移动 Picker 仍隐藏元数据目录。用户自己配置的 `excludedFolders` 仍保留全局屏蔽能力。
2. 普通树节点固定使用 `folder`，与 Picker 的 `folder-closed/folder-open` 不一致。复用同一动态图标映射；自定义图标与颜色优先级不变。元数据目录禁止排序及维护动作，但可折叠查看目录结构。
3. 旧侧栏文件夹仅显示递归索引数。新增物理 Vault 目录计数：*直接文件数 · 含子文件夹的递归总文件数*，两者相同只显示一个数。计数忽略临时结果筛选与结果排除，尊重用户的全局排除。元数据文件仅进入物理目录计数，绝不进入索引/结果或批量管理。文件夹标题/搜索结果的“可检索文件数”仍取索引，和物理计数不一定相等。
4. 原 `_navigationCandidates` 对“结果隐藏文件夹/附件类型”也执行过滤，违背“导航范围不受结果精筛影响”的基线规则。本轮将其和 `isResultMetaVisible` 分离，仅导航候选独立；结果实际过滤、全局索引屏蔽保持原样。
5. 自动分组线 `border-top` 被页面内边距截短，之前候选的手动分割线延伸也未与自动线使用同一可见宽度。现在两者画为 1px 横贯导航内容区的同一色值 `--ls-divider`；手动线保留虚线/自定义颜色/排序删除等设置。文件夹双数计数单独留 9ch 右侧空间，计数色统一到 `--ls-muted`。

## 测试边界
详见交付报告。浏览器专项使用 Chromium 模拟 Obsidian，不能代替 iPhone WebKit 或真实仓库的完整主题/插件组合。严禁把这版称为正式冻结基线，未经用户确认不修改现有 manifest、data.json、笔记或元数据目录。
