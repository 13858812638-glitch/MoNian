# 结果滚动职责精简 · 2026-10-24

唯一开发基线为上一轮完整交付 `b2dee87`。本轮维护候选只修改 `src/features/results/viewport-geometry-methods.js` 的两个方法；未晋升冻结版本。

## 根因与边界

沿 `SearchView.onOpen → SearchCore → attachViewport → handleScrollLoad / _markNativeScroll → _settleNativeScroll` 检查了事件、定时器、清理、几何补偿、结果索引与共享状态的阻塞/恢复链。还核查了结果点击/批量/键盘路径、会话保存、移动侧滑及现有 CSS/Style Settings 职责。没有修改样式、DOM、视觉 Token、设置、Popup、焦点、索引结构或共享状态模型。

原实现对结果区任意鼠标按下，以及空格等控件按键，在没有滚动时也启动 180ms 滚动停稳事务。这个状态会临时阻塞索引与跨窗口查询消费。停稳再调用 `_notifyStateChange`，重新捕获、比较、发布没有变化的查询并同步左侧导航，只为保存当前窗口位置。

- 删除 viewport Owner 的 `pointerdown`、`keydown` 捕获监听及其回调。真正的鼠标滚动条拖动和键盘滚动由现有 `scroll → handleScrollLoad` 处理，不再把普通点击当成滚动。批量选择自身的 pointerdown 焦点规则继续保留。
- 停稳调用 `onStateChange` 保存宿主视口，取代查询级通知。此前的 `_scheduleResultIndexUpdate` 保留，既恢复待处理索引，也通过现有 coordinator 恢复待处理共享查询；没有新增缓存、事件状态或第二个调度器。
- 触摸与滚轮的提前滚动意图、移动侧滑、滚动中几何补偿、样式变更延后处理、程序定位排除、卸载取消均沿用原实现。触摸结束需要释放既有阻塞，不能直接当成多余监听删除。
